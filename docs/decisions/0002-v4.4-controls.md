# ADR 0002：v4.4 P2 的五个控制点

- 状态：Accepted
- 日期：2026-11-10
- 决策人：Human Decision Owner + Agent Maintainer

## 背景

`docs/ROADMAP.md` 的 v4.4 P2 有五项：低风险 24h 默认 + 假设、队列抢占、单一源生成、视觉回归工具化、发布自动化。它们的共同约束是：

- 只依赖 Python 3.9+ 标准库，迁移包里没有第三方依赖；
- 每条规则都能在 CI 里用 fake CLI 单测，不依赖真实 GitHub / Multica / 浏览器；
- 不放松不可协商的底线：人类门禁、独立验证、main 只由人类、证据优先、失败显式；
- 项目事实（工具、断点、阈值、仓库、运行时）只放项目配置，不进小队默认值。

## 决定

### 1. 低风险 24h 默认 + 假设

- 仅 **R0/R1、可逆、无外部契约、非 Program 子级** 的变更可以启用；项目级 opt-in 必须由人类记录（`project_opt_in.by` / `at` / `scope`）。
- 人类默认应仍走 H1；项目 opt-in 后，Lead 在 H1 卡发出满 **24 小时**、且只提醒一次后，可把 H1 记为 `assumed`，并在 manifest `autonomy` 块记录假设（`statement / owner / recorded_at`）。
- H3 仍是人类批准，**不可由假设替代**；H1 被人类推翻时记 `override`，`decision: rejected` 时 H3 失败，`human_gate_restored` 时必须回到人类 H1 批准。
- 校验：`scripts/policy.py check --profile h3` 调用 `validate_autonomy`；`scripts/autonomy.py check|deadline` 可单独审阅。
- 人类动作数不变：Quick 1、Standard 3、Program 4–5（假设只消除“沉默等待”，不新增门）。

### 2. 队列抢占

- `scripts/queue.py` 是确定性调度器：输入运行中/排队中的工作项，输出派发顺序与抢占决策。
- 规则：S0 抢占任何非 S0 运行项；S1 抢占 S2–S4（任何工作道）；同 severity 内 Program 合并窗口打开的项优先，其余按入队时间 FIFO；同刻按 `id` 稳定排序。
- 抢占只改变执行顺序，不改变门禁、验收或人类动作；被抢占项保留 branch/head/write_lock，恢复时先重跑受影响测试。
- Quick 严格 FIFO；程序合并窗口是唯一允许越过 Quick 的例外。

### 3. 单一源生成

- 新增 `sources/squad.json` 作为**唯一源**：kit 元数据、skills 目录、agents 绑定、Squad 名册、`kar-squad-profile` 默认值。
- `scripts/generate.py --check|--write` 生成 `skills.json`、`agents.json`、`squad/KAR-Delivery-Squad.json`、`bootstrap.json`、`skills/kar-squad-profile/squad.json`。
- 选择 JSON 而不是 YAML：迁移包只依赖标准库，YAML 需要第三方解析器；JSON 同样满足“单一源”目标。
- 生成文件头不再手改；`make check` 先跑 `generate.py --check`，漂移即失败。Agent/Skill 的散文正文仍是人类/Agent 编写，不进生成器。

### 4. 视觉回归工具化

- 项目事实文件（如 `multica/project/visual.json`）声明：工具与命令、断点、主题、阈值、关键界面。
- `scripts/visual.py init|check|capture`：`init` 生成模板，`check` 校验覆盖与阈值，`capture` 按声明的命令逐屏/断点/主题采集，输出可审计的结果 JSON。
- 覆盖要求：每个界面 × 断点 × 主题恰好一条结果；关键界面用更严阈值（默认 0 差异）；工具不可用或采集失败 → 显式失败/阻塞，不写 PASS。
- 结果摘要写入 manifest `visual_regression`；`ui_affected: true` 时 H3 必须有该块且 `passed: true`。
- 截图等大文件只放项目证据目录，不进本仓库与迁移包。

### 5. 发布自动化

- `scripts/release.py check|plan|tag|github-release|attach|publish`：版本/CHANGELOG/干净树检查，打 tag 并 push，创建 GitHub Release，把发布包作为附件评论到 Multica issue。
- `scripts/deploy.py`：一键 `dry-run → apply --update → verify`，任一步失败即停；默认 dry-run，`--apply` 才写工作区；bootstrap 自动备份。
- 人类仍拥有发布批准与部署批准：`publish` / `tag` / `deploy --apply` 必须带 `--approved-by <human>`（deploy 用 `--approved-by`），没有批准只打印计划。
- 外部命令（`git` / `gh` / `multica` / bootstrap / verify）均可注入路径，CI 用 fake 命令验证参数与顺序，不触网。

## 后果

- 五条新控制点都有独立脚本、单测、文档与 `make check` 入口；失败显式，不静默降级。
- manifest v2 增加 `autonomy`、`ui_affected`、`visual_regression` 三个可选块；H3 对 `assumed` 门与 UI 变更强制校验。
- 版本升到 4.4.0；配置手册、Skills、Agents、Squad、迁移包与测试同步。
- 风险：低风险假设可能放过错误假设——用项目 opt-in、可逆、24h、单一提醒和 H1 推翻兜底；发布自动化的不可逆动作全部要求人类批准参数。

## 备选方案

| 方案 | 为什么不选 |
| --- | --- |
| 继续用三份手写 JSON + 文档漂移检查 | 只能事后发现漂移，不能消除；生成器可从根上保证一致 |
| 引入 PyYAML 支持 YAML 源 | 迁移包要求零第三方依赖；JSON 已能表达同一结构 |
| 全自动跳过 H3 | 违反“人类拥有合并决定权”的宪法级不变式 |
| 视觉回归内嵌浏览器/图像库 | 迁移包与 CI 无法保证依赖；改为工具适配器 + 结果校验 |
| 发布脚本直接推 main / 自动部署 | 违反 main 由人类掌握；自动化的边界是机械步骤，不是批准 |

## 复审条件

- 平台提供原生调度/队列或发布流水线能力；
- 项目普遍使用 YAML 配置且迁移包允许第三方依赖；
- 低风险假设出现逃逸缺陷（S2+），需要提高阈值或取消 opt-in。
