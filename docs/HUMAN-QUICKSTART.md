# 人类快速上手（1 页）

你的工作只有三个词：**决定、选择、指定人**。其余由 Agent 执行并附证据。

## 三个命令

- `/approve`：同意当前这一步（所有门通用）。
- `/init`：项目初始化，一个项目一次。
- `/tour`：5 分钟导览，只读、不改状态；不知道怎么回就先发它。

其他都用大白话：“把 X 改成 Y”“先停”“退回”“到哪了”“验收找 A，方案找 B”。

## 5 分钟走完一道门

1. **看第一行**：卡的开头是“需要你：确认需求 / 确认方案 / 验收与合并”，不是背景。
2. **看“我检查了”**：3 项检查；哪项 `fail` 或 `n/a` 会在“理由”里说明。
3. **看版本**：括号里的版本/SHA 就是这次批准的绑定物；换版本要重新批。
4. **回一行**：`/approve`，或“批准 v1.2”；要改直接说“把 X 改成 Y”，不用写长文。
5. **不回复**：保持等待；24h 只提醒一次；不自动通过、不代批。

拿不准就发 `/tour`。Lead 会用 ≤5 条消息带你看懂当前这张卡，不要求你读手册。

## 一张卡长什么样

```text
🟡 需要你：确认需求基线（v1.2 / a1b2c3）
谁决定：你（Decision Owner）
先看：3 分钟摘要 → <链接>；原型 → <链接>
我检查了：① 范围与验收标准一致 ② 原型版本/SHA 一致 ③ 证据可复现
理由：需求与原型覆盖全部 P0，范围未漂移
附条件：无
回复：/approve　要改：直接说“把 X 改成 Y”
不做：停在这里，不会自动通过；24h 后只提醒一次
```

- 表情、沉默、“看起来还行”不算批准；Lead 会复述并绑定版本/SHA。
- 每个 Decision Owner 同时最多 2 个待决策；多出的排队。
- 草稿会提前 ≥10 分钟发给你异步看；看到问题直接说，记入决策台账，不重开一轮。

## 你的责任

- 在 SLA 内回应（默认 24h）；指定备份人。
- 批准前至少看 1 页摘要；附条件批准写清条件。
- 不替 Agent 跑测试、对 diff、查配置。
- 不把 token、密码、生产数据发到 issue。

## R3 你会多看到什么

认证/授权、支付、密钥、不可逆数据、合规属于 R3。除了 3 道门，还会多一张“安全 overlay”证据：威胁模型、权限矩阵、密钥/依赖扫描、回滚演练，以及一位独立安全评审人的结论。安全评审人的 pass 不代替你的批准。

## 你要改小队配置时

1. 在 **KAR Squad OS** 项目开 issue，写目标、验收、影响、回滚。
2. Agent 在分支实现；CI 绿后你评审 PR。
3. 你 Approve 后合并、打 tag、构建 release。
4. Agent 部署到工作区并 `verify.py`；执行前自动备份。

## 不会操作时

发 `/tour`，或直接问“现在要做什么”。Lead 会给你下一步；不要猜，也不要跳过门禁。
