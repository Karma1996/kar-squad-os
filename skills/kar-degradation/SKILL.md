# 目的
失败时优雅停下、保留证据、给出可执行的解除条件；不静默降级。

# 触发
运行失败、环境/权限缺失、写锁冲突、分支落后、合并失败、原型漂移、安全问题、人类长期不响应。

# 一、失败分类

| 类型 | 处理 |
| --- | --- |
| 临时故障（网络、CI 抖动） | 最多重试 2 次；记录命令/日志；不重复派发同一工作 |
| 环境/权限缺失 | blocked；写所需输入/权限；通知 Lead/人类 |
| 写锁冲突 | 立即冻结写者；保留 worktree；人工比对后只留一个写者 |
| 分支落后 | 让 Dev 合并 origin/develop，重跑受影响检查；语义冲突需 Reviewer 复核 |
| 合并失败 | 冻结合并列车；保留已合入仓；人类决定回滚/前向修复/拆分 |
| 原型漂移 | 停止实现；提交 DECISION-REQUEST；重新批准或修代码 |
| 候选失效（late push / 文档 SHA 变化） | 旧 A4/A5 结论作废；`manifest.py check` 报 LATE PUSH/STALE；重跑受影响测试并重新 `freeze --write` |
| 安全问题 | 立即停止、保留证据、升级 Lead 与人类；不合并 |
| 人类长期不响应 | 保持等待；24h 提醒一次；绝不代批 |

# 二、BLOCKED 格式

```text
BLOCKED — {issue} {stage}
原因：{一句话}
已尝试：{动作 + 结果 + 命令/退出码}
需要：{输入/权限/决策}
解除条件：{可验证}
影响：{范围/时间}
```

# 三、重试

- 临时故障最多 2 次；每次记录日志。
- 两次失败或缺少环境/权限：blocked，写解除条件。
- 不静默换 Agent；不降低验证标准；不重复派发相同工作。

# 四、写锁冲突

1. 立即冻结写者，停止 push/写文件。
2. 保留 worktree 与现场。
3. 人工比对差异，只保留一个写者。
4. 另一个写者的有效改动由保留者合并或重做。
5. 记录冲突原因，进入复盘候选。

# 五、分支与合并

- develop 前进：Dev 合并 origin/develop，重跑受影响检查；冲突需 Reviewer 复核。
- 多仓合并中途失败：冻结合并列车；保留已合入仓；人类在回滚/前向修复/拆分之间逐次决定；不自动继续。
- 重新验证，不以旧批准覆盖新 SHA；先跑 `scripts/manifest.py check --profile freeze`，失败就不算候选。

# 六、原型漂移

- 实现与已批准原型出现可见差异：停止，提交 DECISION-REQUEST（前后对比、影响、建议）。
- 原型变化：更新版本/SHA；A4/A5 结论失效；必要时重开 H1/H2。
- 不静默改原型或代码；不以“像素差异小”跳过。

# 七、安全

- 发现 secrets、后门、生产数据、越权：停止、保留证据、升级、轮换凭证；不合并、不扩散。
- 不把密钥写进评论/日志/文档；需要密钥时给 Web 设置路径。

# 八、人类不响应

- 保持等待；24h 只提醒一次（写 `reminder_sent_at` / `reminder_count: 1`）；不代批、不自动通过。
- 每个 Decision Owner 待决策 ≤2，超出由 Lead 排队；`scripts/human_wip.py check` 盘点。
- 有备份人则通知备份人；没有则继续等待，记录 `waiting_human`。
