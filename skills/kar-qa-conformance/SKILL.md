# 目的
在干净、可复现的环境独立验证候选，包括像素级原型一致性；产出可信的 A5 报告。

# 触发
候选冻结后启动；与 Reviewer 并行绑定同一 candidate manifest，不等待 A4 通过。

# 一、确认待测对象

issue、`candidate/<KEY>-<digest>`、branch、head SHA、构建号、部署环境、A4 结论（如已出，不等待）、测试设计与用例、开发说明、CI、已批准原型版本/SHA/模式。

开工先跑 `scripts/manifest.py check --profile freeze`，确认 candidate tag/digest 与各仓 head 一致；失败先停，不测旧候选。

head/构建/配置/原型/candidate digest 变化 → 旧结论失效，重测受影响范围并记录新的 tag。

# 二、干净环境

- 从干净状态安装依赖、构建、部署。
- 记录 OS、运行时、数据库、浏览器、脱敏环境变量、commit SHA。
- 冒烟先跑通；失败则停止扩展，先报环境/构建阻塞。

# 三、执行

A. 冒烟：核心路径。
B. 验收：逐条 P0/P1；记录实际结果与证据。
C. 功能/边界：正常、异常、边界、权限、状态、并发、幂等、迁移。
D. 回归：受影响模块 + 核心回归集。
E. 非功能：按设计阈值执行性能、安全、兼容性、可访问性；记录测量方法与环境。
F. 探索式：30–60 分钟；关注用例之外的真实风险。
G. 原型一致性：见下。
H. 缺陷：复现、分级、记录最小步骤与实际/期望；一个缺陷一条评论。
I. 报告：更新测试验收文档；给 A5 结论、风险、H3 建议。

# 四、像素级原型一致性（模式 B）

对每个关键 SC、每个项目断点、每个支持的主题：

| 维度 | 要求 |
| --- | --- |
| 页面/导航 | 与原型一致，无缺失页面/入口 |
| 布局/间距/字号/颜色/圆角/阴影 | 使用项目 token；关键区域无可见差异 |
| 状态 | loading/empty/error/success/权限/校验齐全 |
| 响应式 | 逐档截图一致 |
| 组件形态 | 与项目组件库一致，无第二套视觉语言 |
| 文案 | 与原型一致（允许数据差异） |
| 可访问性 | 对比度、焦点、键盘可达 |
| 像素差异 | 视觉回归；阈值按项目配置；关键区域无可见差异 |

方法：

1. 用固定 fixture；动画/过渡在截图前冻结；关闭随机数据。
2. 截图命名 `SC-xxx-{breakpoint}-{theme}.png`，放 `evidence/screenshots/`。
3. 原型渲染截图与实现截图并排；用自动化视觉回归优先，没有工具则人工逐区域比对并记录。
4. 字体不可用、浏览器渲染差异（抗锯齿/hinting）可请 Decision Owner 书面豁免；记录证据、范围、影响。
5. 结构性差异、状态缺失、权限错误、断点错位：阻塞，不得豁免。

# 五、缺陷分级

- S0：数据丢失、安全事件、生产不可用、不可逆损坏 → 立即停止，通知 Lead 与人类，保留现场。
- S1：核心流程不可用且无替代 → 必须修复并回归。
- S2：重要功能错误，有绕行 → 必须修复或人类书面接受风险。
- S3：一般缺陷/体验 → 可附条件通过，但需豁免记录、责任人、计划。
- S4：文案/细节 → 记录，不阻塞。

验收前 0 个未关闭 S0/S1/S2；S3 需人类书面豁免；S0–S3 修复必须有回归测试。

# 六、可复现与 flaky

- 每个失败可复现；不能复现标 flaky，说明重试次数、环境、风险，不得直接计为通过。
- 允许一次隔离重跑，但不能改断言、跳过、放宽阈值。
- 环境失败与产品失败分开；环境阻塞 → BLOCKED，不写 PASS。

# 七、A5 报告

测试范围/方法、环境/数据、执行摘要（通过/失败/阻塞/跳过）、FR/AC 逐项结果与证据、缺陷清单、回归、非功能、原型一致性（截图/差异/豁免）、风险/限制/flaky、A5 结论、H3 建议、证据索引、变更记录。

# 八、交接与禁止

HANDOFF：stage=qa、verdict、candidate tag/digest、head、report、tests、defects、prototype_conformance、evidence、metrics、recommended_next。

不修代码/不改测试期望；不合并；不部署生产；不代替人类验收；不把 flaky 计为通过；不无证据宣称像素级通过。
